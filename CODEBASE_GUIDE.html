LEETT — CodeArena Codebase Guide

A full-stack competitive coding platform: practice problems with a Monaco editor, run code against test cases, and duel other users in real-time battle rooms with Elo ratings. The repo is split into client (React + Vite) and server (Express + Prisma + Socket.IO).

What this project does

Solo practice

Browse published problems, read constraints and samples, write code in multiple languages, run against sample input, and submit for full grading (visible + hidden tests).

Live battles

Create or join a room by code, pick difficulty, ready up, host starts the match. First correct solve (or timeout/forfeit rules) ends the battle; Elo updates and rematch is supported.

Social & progress

Profiles, leaderboard by rating, submission history, dashboard progress, theme toggle, JWT auth with protected app routes.

Admin

Users with ADMIN role can create/update/delete problems and manage test cases via REST (protected middleware).

Product name in the UI: CodeArena (client/src/constants/app.js). Workspace folder name: LEETT.

Architecture

One Node process serves REST under /api/* and WebSockets on the same port. The client talks HTTP for CRUD/submissions and sockets for battle lobbies.

┌─────────────┐ REST (Axios) ┌──────────────────┐ │ Browser │ ────────────────────► │ Express (app.js) │ │ CodeArena │ │ + middleware │ └──────┬──────┘ └────────┬─────────┘ │ │ │ Socket.IO (JWT in handshake) │ Prisma └──────────────────────────────────────►│ PostgreSQL │ Online Compiler API ◄───┘ executionService (submissions / run)

Server entry flow

  1. server.js validates env (DATABASE_URL, JWT_SECRET), creates HTTP server from app.js, attaches Socket.IO, starts battle timeout sweeper, connects Prisma, then listens (default port 5000).
  2. app.js mounts routes, security headers, JSON body limit 100kb, CORS from CLIENT_URL (default http://localhost:5173).

Client entry flow

  1. main.jsx → React Query provider, toast UI, App.jsx.
  2. AppRouter.jsx defines public routes (landing, login, register) and protected app shell (AppLayout) for dashboard, problems, battles, leaderboard, profile, settings.
  3. API base: VITE_API_BASE_URL or http://localhost:5000/api; socket: VITE_SOCKET_URL or http://localhost:5000.

WebSockets (battle rooms)

Connection authenticated in socketAuth (same JWT as REST). Handlers in room/roomSocketHandlers.js.

Client → server eventBehavior (short)
create-roomHost creates lobby; optional difficulty filter
join-roomJoin by room code
player-ready / player-unreadyReady state; host can start when rules satisfied
set-difficultyLobby difficulty (host)
request-rematchPost-battle rematch flow
leave-roomLeave lobby; forfeit if in battle
disconnectGrace period in lobby; battle disconnect does not auto-remove player

Server → client: socket-connected, room-update, battle-end, battle-activity (opponent submission activity), error payloads on failed actions.

Room channel name = roomCode (players join Socket.IO room with that id).

Code execution pipeline

  1. Client sends source + language + problem id (and optional battle context) to POST /api/submissions or POST /api/submissions/run.
  2. submissionService loads problem test cases (run may use sample only; submit runs hidden too).
  3. executionService calls onlineCompilerProvider per test case with stdin and time limits from the problem.
  4. Outputs are normalized (line endings, trim) and compared; aggregate status → SubmissionStatus (AC, WA, TLE, etc.).
  5. Battle submissions go through battleService.validateBattleSubmission then may finalize the room on AC via winner/Elo logic.

Requires ONLINE_COMPILER_API_KEY in server env; without it, execution fails (startup warns).

Battles & ratings

  • room/roomService.js — room codes, player lists, start battle, problem selection, serialization for clients.
  • battle/battleService.js — submission validation, finalize on solve/forfeit/timeout, Elo via battle/rating.js, emits socket updates.
  • battle/winner.js — outcome rules, battle deadline from startedAt + durationMs (default 30 minutes).
  • startBattleSweeper() — periodic job closes expired IN_PROGRESS battles (survives restarts).

Run locally

Prerequisites

  • Node 20+ (CI tests 20.x and 22.x)
  • PostgreSQL database
  • Online compiler API key (for run/submit)

Server

cd server
# .env: DATABASE_URL, JWT_SECRET, ONLINE_COMPILER_API_KEY, optional CLIENT_URL
npm install
npx prisma migrate deploy   # or migrate dev
npm run seed                # optional sample data
npm run dev                 # nodemon, port 5000

Client

cd client
npm install
# optional: VITE_API_BASE_URL, VITE_SOCKET_URL
npm run dev                 # Vite, default http://localhost:5173

Helpful scripts: npm run import:problems, npm run make-admin, npm run seed:execution (server).

Continuous integration

.github/workflows/node.js.yml on push/PR to main:

  • server job: npm ci, prisma validate/generate, npm test (matrix Node 20 & 22)
  • client job: npm ci, npm run lint, npm run build

There is no root package.json; install and run each package separately.
